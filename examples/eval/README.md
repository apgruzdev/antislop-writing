# Проверка на практике

Здесь лежат сырые тексты, которые написали модели с навыком `antislop-writing` и без него. Любой может перемерить их: `python3 examples/eval/measure.py`.

## Как проводилась проверка

- Четыре задачи. A: объяснение в чате («что такое идемпотентность в HTTP API»). B: раздел README с заданными фактами. C: вступление README с заданными фактами. D: открытый вопрос в чате («зачем записывать ADR»).
- Условия: без навыка (`baseline`) и с навыком на уровнях 100, 80, 60, 40. Не все задачи прогнаны на всех уровнях: смотрите, какие файлы лежат в папке.
- Каждый прогон делал отдельный субагент OpenCode с чистым контекстом в сессии, где писался репозиторий. Модель явно не фиксировалась.
- «С навыком» значит: агент читает `SKILL.md` и справочники. Линтер агенты не запускали.
- Тексты измерены линтером `antislop_lint.py` по одной линейке: уровень 80. Режим `reply` для чатовых ответов (A, D), `document` для README (B, C).
- Файл `B-readme-section/level-100-before-fix.md` — первый прогон. Он показал слабость: глоссарий и дубль шага «сделайте бэкап». После правки правила E2 прогон повторён (`level-100.md`).

## Что видно

- Формат и объём. С навыком исчезают заголовки, таблицы, жирные лид-ины и итоговые «Что запомнить». Ответ A стал короче на 17–32%, вступление C — почти вдвое.
- Выдумка. В базовом C модель дописала «их удобно искать по дате». Такого факта в задаче нет. С навыком в C этой фразы нет.
- Ползунок меняет регистр, а не длину предложений. На 100 в ответе A нет списков, термин объяснён сразу, тон справочный. На 80 есть маркированный список методов. На 40 появляется разговорная речь («Нужно это вот зачем», «Два места, где обычно путаются»). Средняя длина предложения почти не меняется (7,6–9,7 слова в A), потому что базовые тексты тоже короткие.
- Задача B слишком проста. Все факты заданы, сорить нечем. По ней навык мало что показывает.

## Чего эта проверка не доказывает

- По одному прогону на условие. Это иллюстрация, не статистика. Другой запуск даст другие числа.
- Линтер мерит соблюдение правил, а не пользу читателю. Он написан по тем же правилам, что и навык. Нулевое число замечаний не означает, что текст хороший.
- Читатели не участвовали. Мы не проверяли, понятнее ли текст людям.
- Одно семейство моделей. Другие модели могут вести себя иначе.
- Нет сравнения с исходными навыками. `simple-english` и `redaktura` отдельно не прогонялись, поэтому выигрыш от сборки против каждого из них не измерен.

Если вы хотите проверить сами: положите свой текст в файл и выполните `python3 skills/antislop-writing/scripts/antislop_lint.py --level 80 файл.md`.
